# PopDeck 0.1.9 release validation

Validated on 2026-10-17, macOS 27.0.1 / Xcode 27.0, Apple Silicon.

## Tests and packaging

- Independently buildable Free source: 19 tests passed.
- Full distribution source with external private PRO overlay: 68 tests passed, including activation signatures, invalid/tampered licenses, offline persistence, personal multi-Mac use, entitlement gates, retained configuration, ring geometry and input routing.
- Build-isolation and public-source boundary checks passed. A stale shared Free/PRO compilation cache was preserved and replaced with a clean compilation before the successful full test run.
- Production identity is `com.tangfanx.popdeck`, version 0.1.9 / build 10, minimum macOS 14, arm64. The downloadable binary includes Free mode and optional locally activated PRO; public source remains Free only.
- Candidate built only at `.build/release-019/PopDeck.app`. Deep strict code-signature verification passed. Distribution retains ad-hoc signing; Developer ID and notarization remain unavailable.
- DMG SHA-256: `429cb84406236f46c02fbca922880e4ff92aadfee28a39780471bfb6691a2c7d`. Existing Sparkle EdDSA key verified the archive signature; appcast enclosure length matches the archive.
- Bundle resources contain public verification keys only: no signing private key, sales ledger, activation grant or Apple runtime-only wheel audio.

## Real updater flow in an isolated copy

The installed 0.1.8 / build 9 app was copied read-only. Both fixture bundles use `com.tangfanx.popdeck.upgrade-validation-019`, a localhost-only feed and their own preferences. Only fixture bundle metadata and ad-hoc signatures changed; neither old nor new application code was instrumented. The old fixture used a separate TMPDIR for its legacy single-instance lock.

On cold launch, without a manual update check, Sparkle presented 0.1.9 available / current 0.1.8. Install Update downloaded the separately signed fixture DMG, replaced the old fixture and relaunched into 0.1.9 (10). The installed executable’s `__TEXT,__text` SHA-256 matched the official candidate: `fda88711de167df9b9c162d7e730bca6c195600bee5359725880983ed2687c66`.

All three seeded legacy launcher entries retained their IDs, titles, action kinds and values. Legacy showItemNames=true and glassStrength=0.5 preferences remained intact. This validates actual Sparkle replacement using isolated metadata; the original production installation was not used as a test target.

## Native Free and PRO checks

- Upgraded, unlicensed app displayed one circle and the support page. Five additional commands were added through native UI, reaching 8/8 launch items. Duplicate commands were rejected. A command clicked in the actual panel wrote its expected temporary marker file.
- Adding a ring while unlicensed opened PRO activation. Invalid activation was rejected.
- Existing separate author test grant activated successfully through pasted code, without touching the paid ledger. The support page disappeared. Added a second ring, a command set and a group through native editors.
- Both an outer-ring command-set child and an expanded-group command ran from the actual panel and wrote their expected marker files. No underlying first-circle item intercepted those clicks.
- After quitting and reopening the isolated app, authorization, both circles, all eight first-circle items, the group and command set remained available.

## Preserve the real installation

File SHA-256 fingerprints of `/Applications/PopDeck.app`, the production preferences and existing production/Dev license files were identical before and after testing. The real app stayed 0.1.8 / build 9. No installation, preference import, activation, updater consent change or TCC reset was applied to the real production identity. The owner can reopen that original installation after publication to observe its normal update prompt.

Older macOS fallback was not visually retested on separate hardware. Verification screenshots, logs and fixture artifacts remain local under `.build/upgrade-019` and `.build/release-019`.
