# PopDeck 0.1.7 release validation

Validated on 2026-10-16 using macOS 27.0.1 / Xcode 27.0.

- Release identity: 0.1.7, build 8, minimum macOS 14, arm64.
- Five automated regression tests passed: shell syntax/working directory, bounded stderr and nonzero status, command validation, persistence/legacy decoding, and plain-text shell punctuation.
- Release `.app` and DMG built successfully; nested app code signatures passed `codesign --verify --deep --strict`.
- The production DMG passed Sparkle EdDSA signature verification using the existing signing account; its size matches the production appcast enclosure.
- Production DMG SHA-256: `9389cd959337346bbf77086fb36582c0fecf30198ac08036babcd905ced78570`.

## Upgrade test

The old 0.1.6 source at commit `17c2a84` was rebuilt with a test-only entry point that calls its existing Sparkle check action. Both test apps used the separate identifier `com.tangfanx.popdeck.upgrade-validation`, a local-only HTTP appcast, and their own preferences. The new test copy contained the production candidate's compiled executable, with only fixture bundle metadata and code signatures changed. The formal user's preferences and `/Applications/PopDeck.app` were not modified.

Sparkle's standard UI offered 0.1.7 while running 0.1.6, downloaded the signed test DMG, reached “Ready to install”, then installed and relaunched. The installed bundle reported 0.1.7 / build 8 and its relaunched process ran from the updated test installation. Its `__TEXT,__text` machine-code digest matched the production candidate. A seeded legacy launcher entry was preserved exactly; glass intensity remained 0.5.

The fixture DMG had a separate EdDSA signature because its identifier and local feed differ from production. The formal DMG's signature was verified independently. This test validates the old-source Sparkle upgrade path in an isolated identity; it does not claim that the untouched public 0.1.6 binary was installed over a user's real app.

## Cold-launch automatic check

The isolated installed candidate was also cold-launched with its bundle version metadata temporarily lowered to 0.1.6 / build 7 and automatic checking enabled in the test-only preference domain. No `--validate-upgrade` argument was supplied and no menu was opened. Its production startup code fetched the local feed and Sparkle presented the 0.1.7 update alert. This separately verifies launch-time initialization and the consent-gated background check. Test metadata was restored after dismissing the prompt.

## Runtime checks completed during development

Native edge refraction was verified with a grid in the actual circular panel, including a focused/non-focused comparison and a nonzero native tint strength. The 50-intensity outside-click dismissal and re-opening flow were checked after removing the delayed close on focus loss. The settings slider persists across launches. The website candidate displays 0.1.7 and the new command and native-glass features in its translation content.

## Distribution limits

The app continues to use ad-hoc signing and is not Developer ID signed or notarized, matching the existing release channel. The older-macOS blur fallback has not been visually tested on a separate older-system machine. Diagnostic grid modes are excluded from release builds.
