# PopDeck 0.1.8 release validation

Validated on 2026-10-16 with macOS 27.0.1 / Xcode 27.0.

## Native material correction

Apple's Materials HIG and installed macOS 27 SDK were checked. NSGlassEffectView exposes regular and clear styles and a tint color; it has no documented independent blur-strength scalar. The former control varied black tint, so it was replaced with a native style picker. Both variants leave tintColor nil. Regular is the default, including when a legacy glassStrength value exists; the legacy preference is not rewritten.

The actual circular panel was run in an independently identified debug bundle, with the same split black/white grid behind both variants. Regular visibly diffused the grid and improved bright-side legibility. Clear preserved the grid and showed prominent edge refraction. Clear selection persisted after quitting and reopening the test app. No system appearance or accessibility preference was changed. The older-macOS fallback was not visually tested on separate hardware.

## Automated and artifact checks

- All five existing command/persistence/editor regression tests passed.
- Release identity: 0.1.8 / build 9, minimum macOS 14, arm64.
- Production app was built at `.build/release-0.1.8/PopDeck.app`; it was never installed or launched under the production identifier.
- Production app passed deep, strict code-signature verification. Signing remains ad-hoc; Developer ID signing and notarization are not enabled.
- DMG SHA-256: `b330cd16e107111e3707f0a7ee3157e5b59e043e89aa55d8e7a9433bb070842c`.
- Production DMG passed Sparkle EdDSA verification with the existing signing account; enclosure length matched its file size.

## Isolated 0.1.7 to 0.1.8 upgrade

The already-installed 0.1.7 / build 8 app was copied read-only to `.build/upgrade-018/old/PopDeck.app`. Only fixture Info.plist metadata and ad-hoc signatures changed; its application code was not instrumented or rebuilt. Both fixture apps used `com.tangfanx.popdeck.upgrade-validation-018`, a localhost-only feed, and an independent preferences domain. The old fixture was launched with its own TMPDIR to isolate its legacy single-instance lock. No manual check-for-updates action or test-only updater entry point was used.

On cold launch, Sparkle automatically presented “0.1.8 available; current version 0.1.7”. Choosing Install Update fetched the signed fixture DMG. The fixture was replaced and relaunched; its Settings UI reported 0.1.8 (9) and selected Regular by default. The relaunched installed executable's `__TEXT,__text` digest matched the production candidate: `410c5a284b565bfc7c7329e1cff409b99bdf2d194e246104c80ed905dd68fa89`.

The seeded legacy launcher entry survived exactly. showItemNames remained true and the unused legacy glassStrength remained 0.5. The fixture DMG has its own signature because fixture metadata differs from production. The production archive signature was verified separately.

## Preserve the user's real installation

`/Applications/PopDeck.app` remained 0.1.7 / build 8. Its executable and Info.plist SHA-256 values were checked before and after the isolated tests and were unchanged. The formal preferences domain was never imported, written, or used to run a test build. No real automatic-update consent or skipped-version preferences were changed. The final production update prompt is intentionally left for the user to observe by reopening their installed 0.1.7 after publication.
