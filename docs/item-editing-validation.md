# Command editing and icon appearance (development)

Validated 2026-10-17 on macOS 27.0.1. Not a production release.

- Existing commands can be edited from Launcher Items in Settings or the preview context menu. The sheet pre-fills the saved name and shell source. Save updates the existing ID in place; Cancel leaves it unchanged. Validation rejects empty/NUL-containing source and duplicate source belonging to another command. Editing is permitted at the eight-item limit.
- Icon Appearance supports eight original-icon tint colors and one emoji, including flags, skin tones, keycaps and joined emoji. Original file/image icons are desaturated and multiplied by the selected color to retain their detail/alpha; SF Symbols use the selected foreground color. The source file's icon is not modified. Emoji retain their colors. Restore Default clears the per-item appearance after Save.
- Optional iconAppearance persistence preserves legacy entries. The setting preview, item list and live panel use the same icon renderer. File paths, actions, order and item IDs are preserved.
- All eight automated tests passed, including at-capacity edits, duplicate/invalid edit rejection, reload persistence, appearance reset, file-action preservation and emoji validation, plus the previous command/editor/legacy tests. Tests use unique disposable preferences suites.
- UI checks in the independently signed PopDeck Dev: add command; edit name and multiline shell source; reopen to confirm prefill; cancel an edit; select/save/reopen blue tint; invalid multiple-emoji input disables Save; save joined emoji; quit and reopen to confirm persistence; tint a real text-file icon green; inspect both the green file and joined emoji in the actual circular panel; inspect the preview's right-click Edit Command / Icon Appearance entries.
- UI tests never invoked the temporary command. The two temporary fixture entries were removed afterward, leaving existing Dev items intact. No production preference domain was imported or written, and no production app was installed or launched. Production executable, Info.plist and saved launcher/settings fingerprints were compared separately.

The proposed subdivided command-set sector was analyzed only; no group model, UI or execution behavior was added.

## Follow-up: full emoji selector and execution mode

The free-text emoji field was replaced with a dropdown popover containing an offline, lazily rendered Unicode Emoji 18.0 catalog (3,963 fully qualified sequences in nine categories). All entries are selectable; original-icon selection, category filtering and optional English-name/emoji search are available. Newer emoji rendering depends on system fonts. Data source: https://unicode.org/Public/emoji/latest/emoji-test.txt (downloaded 2026-10-17); bundled Unicode License V3 is retained in Resources/Unicode-LICENSE.txt.

Add/Edit Command now has a checkbox, unchecked by default, for Terminal execution. A missing opensTerminal field decodes as false. The selected mode persists and maps into the action; edit sheets prefill it. Silent execution retains the previous behavior. Terminal mode writes a private executable .command file, opens it explicitly in com.apple.Terminal via NSWorkspace, and removes the file when the script starts. Command source is passed as one quoted argument to zsh -lc with Terminal's TTY for stdin/stdout. After reporting status the wrapper enters a login shell, keeping the terminal open. It does not use AppleScript or request Automation permission.

Eleven automated tests passed, adding mode default/edit/reload coverage, shell-argument round-trip validation without expansion, and uniqueness/selectability for the full emoji catalog. UI verification confirmed the unchecked default, saved checked state, dropdown count and categories, selection/save without manual emoji entry, and an actual launcher click creating a Terminal-backed shell on a real TTY waiting for read input. Computer-use tooling prohibited Terminal UI access, so automated keyboard-entry/output-screen acceptance was not completed. Cleanup was restricted to the known temporary test command; existing Terminal sessions were not targeted. The temporary launcher entry was removed without restoring an old Dev preference snapshot, preserving any other changes made during testing.
